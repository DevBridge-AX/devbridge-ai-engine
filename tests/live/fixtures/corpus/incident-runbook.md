# 장애 대응 runbook

## 1차 대응

장애 알림은 PagerDuty를 통해 온콜(on-call) 담당자에게 전달됩니다. 온콜 담당자는
알림 수신 후 **15분 이내** 초기 대응(장애 인지 및 상태 페이지 갱신)을 시작해야
합니다(SLA).

## 롤백 명령어

배포 직후 발생한 장애로 판단되면 아래 명령으로 즉시 이전 버전으로 롤백합니다.

```
kubectl rollout undo deployment/api-server
```

롤백 후에는 `kubectl rollout status deployment/api-server`로 정상 기동을 확인합니다.

## 에스컬레이션

15분 내에 장애가 해소되지 않으면 팀 리드에게 에스컬레이션합니다. 30분 내에도
해소되지 않으면 인프라팀장 및 관련 서비스 오너 전체에게 알립니다.

## 사후 보고

장애 해소 후 24시간 이내에 포스트모템 문서를 작성합니다. 문서에는 타임라인,
근본 원인, 재발 방지 대책이 포함되어야 합니다.

## 자주 발생하는 장애 유형

- 결제 게이트웨이 타임아웃: TossPayments 상태 페이지 확인 후 재시도 대기
- DB 커넥션 풀 고갈: 커넥션 풀 사이즈 설정 및 슬로우 쿼리 로그 확인
- 배포 직후 5xx 급증: 즉시 롤백 절차(위 롤백 명령어) 수행
